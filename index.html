1. Network Reconnaissance

Aim: Collect basic domain, DNS and network-path information for stc.ac.in.

Algorithm

  1. Open Terminal or Command Prompt.
  2. Run WHOIS and DNS lookup commands.
  3. Find the domain's IP address.
  4. Trace the network route.
  5. Record the results.

Linux commands

whois stc.ac.in
dig stc.ac.in
nslookup stc.ac.in
traceroute stc.ac.in

Windows commands

nslookup stc.ac.in
tracert stc.ac.in
Remember: WHOIS = domain details • DIG/NSLOOKUP = DNS • traceroute = network hops. TTL = Time To Live.

2. Detect ARP Changes Using ARPwatch

Aim: Monitor changes in IP-to-MAC address mappings on an authorized lab network.

Algorithm

  1. Update package information.
  2. Install ARPwatch.
  3. Enable and start the service.
  4. Review its logs.
  5. Investigate unexpected IP-to-MAC changes.

Commands

sudo apt update
sudo apt install arpwatch
ip addr
ip route
sudo systemctl enable --now arpwatch
sudo systemctl status arpwatch
sudo journalctl -u arpwatch
A changed IP-to-MAC mapping is a warning to investigate, not proof of spoofing.

4. Safe C Buffer Input Demonstration

Aim: Demonstrate bounded input to prevent overflowing a character array.

Algorithm

  1. Start the program.
  2. Declare a character array of size 20.
  3. Read at most 19 characters.
  4. Display the entered name.
  5. End the program.

buffer_demo.c

#include <stdio.h>

int main(void) {
    char name[20];

    printf("Enter your name: ");

    if (scanf("%19s", name) != 1) {
        return 1;
    }

    printf("Hello %s\\n", name);
    return 0;
}

Compile and run

gcc buffer_demo.c -o buffer_demo
./buffer_demo
Remember: name[20] stores up to 19 input characters plus the string-ending character. The width in %19s limits input.

5. Install, Test and Uninstall Snort

Aim: Install an IDS, check its version and test its configuration.

Algorithm

  1. Update packages.
  2. Install Snort.
  3. Check the version and configuration path.
  4. Test the configuration.
  5. Run Snort on the correct lab interface.
  6. Uninstall if required.

Commands

sudo apt update
sudo apt install snort -y
snort -V
ls /etc/snort
sudo snort -T -c /etc/snort/snort.lua
ip link
sudo snort -c /etc/snort/snort.lua -i eth0

Uninstall

sudo apt purge snort -y
sudo apt autoremove -y
Replace eth0 with the real interface name. Snort versions and configuration paths differ; if the shown file is missing, use the installed version's configuration path.

6. Security Logs and Registry

Aim: Examine login events, account changes and startup entries.

Algorithm — Windows

  1. Open Event Viewer.
  2. Go to Windows Logs → Security.
  3. Search relevant event IDs.
  4. Inspect Run registry keys for startup entries.

Windows commands and paths

eventvwr.msc
regedit
HKEY_CURRENT_USER\\Software\\Microsoft\\Windows\\CurrentVersion\\Run
HKEY_LOCAL_MACHINE\\SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Run

Event IDs to remember

4624 - Successful login
4625 - Failed login
4720 - User account created
4726 - User account deleted
1102 - Security audit log cleared

Algorithm — Linux

  1. List log files.
  2. Open authentication logs or system journal.
  3. Search for failed authentication.
  4. Record relevant events.

Linux commands

ls /var/log
sudo less /var/log/auth.log
sudo tail -n 30 /var/log/auth.log
sudo grep -a -i "failed" /var/log/auth.log
sudo journalctl -n 30
sudo journalctl | grep -i "authentication"
sudo journalctl | grep -i "failed"
Some Linux systems use journalctl instead of /var/log/auth.log. Review unfamiliar registry entries before changing or deleting them.

7. Firewall Rules Using iptables

Aim: List firewall rules, allow or block traffic, and inspect logs.

Algorithm

  1. List existing firewall rules.
  2. Add a rule to allow TCP port 80.
  3. Add a rule to drop TCP port 23.
  4. Inspect rules and line numbers.
  5. Save a rules snapshot.
  6. Add a logging rule and inspect kernel logs.

Commands

sudo iptables -L -n -v
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 23 -j DROP
sudo iptables -L INPUT -n -v --line-numbers
sudo iptables-save > firewall.rules
sudo iptables -A INPUT -j LOG --log-prefix "IPTABLES: "
sudo journalctl -k | grep IPTABLES
Remember: INPUT = incoming traffic • ACCEPT = allow • DROP = discard • LOG = record matching packets.
Firewall changes apply immediately. Use a lab system and avoid changing remote firewall rules without a recovery plan.

8. Create a Custom Snort ICMP Alert Rule

Aim: Create a rule to alert on matching ICMP traffic in a lab.

Algorithm

  1. Create a rule file.
  2. Add an ICMP alert rule with a unique SID.
  3. Identify the network interface.
  4. Run Snort with the rule file.
  5. Generate test ICMP traffic and observe alerts.

Create rule file

nano ~/test.rules

Rule text

alert icmp any any -> any any (msg:"ICMP TEST ALERT"; sid:1000001; rev:1;)

Run and test

ip link
sudo snort -c /etc/snort/snort.lua -R ~/test.rules -i eth0 -A alert_fast
ping -c 4 8.8.8.8
Remember: alert = action • icmp = protocol • msg = alert text • sid = rule ID • rev = revision.
This example uses Snort 3-style options and a sample config path. Use the actual config path and interface for your installation.

9. Network Path Using traceroute

Aim: Observe the hops between your computer and a destination.

Algorithm

  1. Open Terminal or Command Prompt.
  2. Enter the destination domain.
  3. Run traceroute or tracert.
  4. Observe hops and response times.
  5. Record the result.

Linux

traceroute stc.ac.in
ping -c 4 stc.ac.in

Windows

tracert stc.ac.in
Remember: Traceroute shows the route; it does not by itself identify the person responsible for an attack.

10. Web Assessment Using OWASP ZAP

Aim: Scan a local training web application for potential security issues.

Algorithm

  1. Install and open OWASP ZAP.
  2. Start a local training app.
  3. Set the app URL as the target in ZAP.
  4. Browse or scan the local application.
  5. Review alerts and severity.
  6. Record findings and suggested fixes.

Install and start ZAP (Ubuntu/Debian packages)

sudo apt update
sudo apt install zaproxy -y
zaproxy

Install Docker and run local Juice Shop

sudo apt install docker.io -y
sudo systemctl start docker
sudo systemctl enable docker
sudo docker pull bkimminich/juice-shop
sudo docker run --rm -p 127.0.0.1:3000:3000 bkimminich/juice-shop

Test local app

curl http://127.0.0.1:3000

Open http://127.0.0.1:3000 in your browser, then target that local URL in ZAP. Keep the Docker terminal running during the test.

Scan only applications you own or have permission to test. The Juice Shop image is intentionally vulnerable and should be kept local for this exercise.
