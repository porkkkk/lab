STUDY UNIT 1

UNIT 1 — Introduction to Cloud Computing

1. Cloud Computing — Definition

Cloud computing is a technology that provides servers, storage, databases, networking and software through the Internet on demand.

Example: Google Drive, Gmail, AWS and Microsoft Azure.

2. Origins and Influences of Cloud Computing

  1. Mainframe computing: One powerful computer serves many users.
  2. Client-server computing: Clients request services from servers.
  3. Distributed computing: Multiple computers work together.
  4. Grid computing: Computers in different locations solve large problems.
  5. Utility computing: Users pay according to usage.
  6. Virtualization: Multiple virtual machines run on one physical computer.
  7. Internet technology: Enables global access to cloud services.

3. Business Drivers

  1. Cost reduction.
  2. Faster service delivery.
  3. Scalability.
  4. Global accessibility.
  5. Business continuity.
  6. Improved collaboration.
  7. Focus on core business activities.

4. Cloud Characteristics

Remember these five:

  1. On-demand self-service: Resources can be obtained whenever needed.
  2. Broad network access: Services are accessible through networks.
  3. Resource pooling: Resources are shared among customers.
  4. Rapid elasticity: Resources increase or decrease quickly.
  5. Measured service: Usage is monitored and measured for billing.

5. Cloud Roles

  1. Cloud provider: Supplies cloud services.
  2. Cloud consumer: Uses cloud services.
  3. Cloud broker: Connects providers and consumers.
  4. Cloud auditor: Checks security, compliance and performance.
  5. Cloud carrier: Provides network connectivity.

Cloud resource administrator: Manages cloud resources, permissions, configurations and monitoring.

6. Cloud Service Models

ModelMeaningExample
IaaSInfrastructure as a Service — virtual machines, storage and networksAmazon EC2
PaaSPlatform as a Service — platform for developing applicationsGoogle App Engine
SaaSSoftware as a Service — ready-to-use online softwareGmail, Microsoft 365

7. Cloud Deployment Models

  1. Public cloud: Services available to multiple customers.
  2. Private cloud: Infrastructure dedicated to one organization.
  3. Hybrid cloud: Combination of public and private clouds.
  4. Community cloud: Shared by organizations with common requirements.

8. Benefits of Cloud Computing

  1. Reduces hardware costs.
  2. Provides scalability.
  3. Offers remote access.
  4. Supports collaboration.
  5. Enables faster deployment.
  6. Provides backup and recovery options.
  7. Reduces infrastructure maintenance.

9. Risks and Challenges

  1. Data breaches.
  2. Privacy issues.
  3. Internet dependency.
  4. Service downtime.
  5. Vendor lock-in.
  6. Data loss.
  7. Compliance problems.
  8. Unexpected costs.
  9. Performance and latency issues.
STUDY UNIT 2

UNIT 2 — Cloud Security and Privacy

1. Cloud Security

Cloud security protects cloud data, applications, accounts and infrastructure from unauthorized access, attacks and damage.

2. Major Cloud Security Issues

  1. Data breach: Unauthorized access to sensitive data.
  2. Data loss: Data disappears because of deletion, failure or attacks.
  3. Insecure APIs: Weak interfaces allow unauthorized access.
  4. Insider threats: Employees misuse their access.
  5. DoS attacks: Excessive traffic makes services unavailable.
  6. Shared technology vulnerabilities: Attacks exploit weaknesses in shared infrastructure.

Prevention: Encryption, backups, MFA, access controls, monitoring and secure configuration.

3. Identity Security

Identity security verifies users and controls their access to cloud resources.

  • Authentication: Verifies who the user is.
  • Authorization: Determines what the user can do.
  • MFA: Uses two or more verification factors.
  • IAM: Manages identities, accounts and permissions.

Example: Password plus OTP protects a cloud account.

4. Five Information Security Principles

  1. Confidentiality: Only authorized users can view data.
  2. Integrity: Data remains accurate and unaltered without authorization.
  3. Availability: Services are accessible when required.
  4. Accountability: Actions can be traced to users or systems.
  5. Nonrepudiation: Evidence helps prevent a person from denying an action they performed.

5. Key Information Security Considerations

  1. Risk assessment.
  2. Access control.
  3. Encryption.
  4. Data integrity.
  5. Availability and recovery.
  6. Privacy protection.
  7. Monitoring and auditing.
  8. Legal compliance.
  9. Incident response.
  10. Shared responsibility.

6. Shared Responsibility Model

Security responsibilities are divided between the cloud provider and customer.

  • Provider: Generally protects physical infrastructure and provider-managed services.
  • Customer: Protects data, identities, permissions and customer-managed configurations.
  • Importance: Clarifies responsibilities and reduces security risks.

7. Cloud Security Standards

  1. ISO/IEC 27001: Information security management.
  2. ISO/IEC 27017: Cloud security controls.
  3. ISO/IEC 27018: Protection of personal information in public clouds.
  4. NIST Cybersecurity Framework: Cybersecurity risk management.
  5. NIST SP 800-53: Security and privacy controls.
  6. CSA Cloud Controls Matrix: Cloud security controls framework.

8. Information Security Analysis in Cloud

  1. Check data protection.
  2. Review identity management.
  3. Examine network security.
  4. Verify encryption and key management.
  5. Review logs and monitoring.
  6. Check backup and recovery.
  7. Verify compliance.
  8. Examine incident response procedures.
STUDY UNIT 3

UNIT 3 — Confidentiality of Data in the Cloud

1. Data Confidentiality

Confidentiality means ensuring that only authorized people or systems can access information.

Example: Encrypting private files stored in cloud storage.

2. Threat Landscape

  1. External attackers: Use phishing, malware and password attacks.
  2. Malicious CSP insiders: Employees intentionally misuse privileged access.
  3. Honest-but-curious CSP: Provider follows service rules but tries to learn customer information.
  4. Compromised co-tenants: Attackers target other customers sharing the same infrastructure.
  5. Malicious or negligent users: Users intentionally or accidentally expose data.

3. Layered Defence

  1. Transport protection: TLS protects data in transit.
  2. Storage encryption: Protects data at rest.
  3. End-to-end encryption: Data is encrypted before upload and decrypted by authorized recipients.
  4. IAM: Controls access to resources.
  5. Key management: Protects encryption keys.
  6. Auditing: Records and monitors activities.

4. Access Control Models

RBAC — Role-Based Access Control

  • Permissions are assigned to roles.
  • Users receive permissions through their roles.
  • Easy to manage in large organizations.
  • Example: Teachers can edit marks; students can view them.

ABAC — Attribute-Based Access Control

  • Access depends on user, resource and environmental attributes.
  • Can consider department, file sensitivity, time or device.
  • Supports detailed access rules.

Difference: RBAC uses roles; ABAC uses attributes and policies.

5. Data Classification

  1. Public: Can be shared publicly.
  2. Internal: Intended for organization members.
  3. Confidential: Restricted sensitive information.
  4. Restricted: Highest-sensitivity information requiring strict protection.

6. Data Lifecycle Confidentiality

Protect information at every stage:

  1. Data creation.
  2. Data storage.
  3. Data sharing.
  4. Data backup or archival.
  5. Data deletion.

7. Cryptographic Solutions

Cryptography: Protects information using mathematical methods.

  • Plaintext: Original readable data.
  • Ciphertext: Encrypted data.
  • Encryption: Converts plaintext into ciphertext.
  • Decryption: Converts ciphertext back to plaintext.
  • Hashing: Produces a digest used to check integrity.
  • Digital signature: Helps verify origin and detect modification.

Five encryption approaches

  1. Symmetric encryption: Uses one shared secret key. Example: AES.
  2. Asymmetric encryption: Uses public and private keys. Examples: RSA and ECC.
  3. Convergent encryption: Derives a key from data; can support deduplication.
  4. Searchable Symmetric Encryption (SSE): Enables searching encrypted data.
  5. Homomorphic encryption: Allows computation on encrypted data.

8. End-to-End Encryption (E2EE)

  1. Data is encrypted on the sender's device.
  2. Encrypted data is uploaded or transmitted.
  3. The cloud stores ciphertext.
  4. Authorized recipients obtain the necessary keys.
  5. Decryption occurs on authorized devices.
  6. The provider cannot read the contents if it does not possess the decryption keys.

Challenges: Key recovery, adding devices, password changes and revoking access.

9. Secure Deletion

Secure deletion ensures that information cannot be recovered through unauthorized means.

  • Delete data according to secure disposal policies.
  • Consider backups, replicas and snapshots.
  • Use cryptographic erasure where appropriate.
  • Protect and securely destroy encryption keys.
  • Verify that required copies have been addressed.

Data remanence: Traces of information that remain after deletion.

10. Cloud Security Arms Race

  1. Attackers develop new attacks.
  2. Defenders improve encryption and access controls.
  3. Monitoring detects suspicious activities.
  4. Patching addresses vulnerabilities.
  5. Security methods evolve continuously.

UNIT 4 — Cloud Forensics

1. Definition

Cloud forensics is the process of identifying, collecting, preserving, examining, analysing and presenting digital evidence from cloud environments.

Example: Investigating unauthorized access to a cloud database.

2. Why Cloud Forensics Is Different

  1. Loss of physical control: The provider manages hardware.
  2. Multi-tenancy: Many customers share infrastructure.
  3. Volatility: Temporary resources may disappear.
  4. Distributed data: Evidence may be spread across locations.
  5. Encryption: Data may be inaccessible without keys.
  6. Large data volume: Millions of logs require automated analysis.
  7. Legal issues: Different countries have different laws.
  8. Provider dependency: Investigators may need CSP cooperation.

3. Cloud Service Models and Forensics

  • IaaS: Access to VM images, operating-system logs and customer-managed resources.
  • PaaS: Mainly application and provider-supported platform records.
  • SaaS: Often depends on provider-generated logs and evidence requests.

4. Stakeholders

  1. CSP: Provides available cloud evidence.
  2. Cloud customer: Supplies account information and local evidence.
  3. Forensic investigator: Collects and analyses evidence.
  4. Law enforcement/regulators: Request or legally obtain evidence.
  5. End users: Their activities may create evidence.
  6. Auditors: May verify procedures and controls.

5. Technical Challenges

  1. Physical hardware is inaccessible to investigators.
  2. Evidence location may be uncertain.
  3. Multiple customers share infrastructure.
  4. Temporary logs may disappear.
  5. Encryption may restrict access.
  6. Evidence integrity must be established.
  7. Huge log volumes are difficult to analyse manually.

6. Legal and Organizational Challenges

  1. Different countries have different laws.
  2. Privacy rules may restrict disclosure.
  3. Provider cooperation may be necessary.
  4. SLAs may not clearly define responsibilities.
  5. Evidence must be separated between tenants.
  6. Chain of custody must be documented.

Data sovereignty: Data may be subject to the laws of the country where it is stored or otherwise governed.

7. Cloud Forensic Process

Memorize these four steps:

  1. Identification: Identify the incident and evidence sources.
  2. Preservation and collection: Save logs and snapshots, calculate hashes and document handling.
  3. Examination and analysis: Examine evidence and reconstruct the timeline.
  4. Presentation: Prepare a report with findings and methodology.

8. Cloud Forensic Methods

  1. Provider-side: Collect CSP logs, snapshots and metadata.
  2. Client-side: Examine browser history, cached files and synced data.
  3. Network forensics: Examine captured network traffic.
  4. Hybrid approach: Combine all three methods for stronger findings.

10. Cloud Data Acquisition

  1. Snapshot acquisition: Point-in-time copy of VM disks or volumes.
  2. API-based acquisition: Collect logs and metadata through APIs.
  3. Live acquisition: Collect RAM and running-state evidence.
  4. Client-side acquisition: Collect local cached or synced data.
  5. Provider-assisted acquisition: Request evidence directly from the CSP.

11. Chain of Custody

Chain of custody is the documented record of evidence collection, access, transfer and storage.

It records:

  • Who handled the evidence.
  • When it was handled.
  • How it was collected or transferred.
  • Where it was stored.
  • Relevant hash values.

Importance: Helps establish evidence integrity and supports legal proceedings.

12. New Cloud Forensic Model

  1. Forensic readiness.
  2. Clearly defined responsibilities.
  3. Separation of tenant data.
  4. Standardized evidence formats.
  5. Automated collection and continuous monitoring.

13. Cloud Forensic Analysis Questions

Investigators must determine:

  1. What happened?
  2. When did it happen?
  3. Who was responsible?
  4. How did it happen?
  5. Which systems or data were affected?
STUDY UNIT 5

UNIT 5 — Analysis of Cloud Digital Evidence

1. Digital Evidence

Digital evidence is information stored or transmitted digitally that can help an investigation.

Examples: Access logs, API logs, VM snapshots, memory captures, network traffic and metadata.

2. Current Approaches to Cloud Evidence

  1. Acquisition: Collect evidence through APIs, logs, snapshots and live capture.
  2. Evidence management: Use hashing, secure storage and chain-of-custody records.
  3. Presentation: Prepare timelines, visualizations and reports.
  4. Court preparation: Establish authenticity, reliability, lawful collection and proper documentation.

3. Forensic Readiness

Forensic readiness means preparing an organization to collect, preserve and use digital evidence when required.

Benefits:

  1. Reduces investigation costs.
  2. Reduces operational disruption.
  3. Improves evidence availability.
  4. Supports compliance.
  5. Speeds up investigations.
  6. Helps deter wrongdoing.

4. Digital Forensic Readiness (DFR) — 10 Steps

  1. Define the business situation.
  2. Identify evidence sources.
  3. Determine collection requirements.
  4. Establish legal collection capability.
  5. Establish secure storage policies.
  6. Monitor effectively.
  7. Specify evidence-release conditions.
  8. Train staff.
  9. Document cases.
  10. Provide legal review.

5. Cloud Forensic Readiness (CFR)

CFR applies forensic readiness specifically to cloud environments.

Main features:

  1. Shared responsibility between customer and provider.
  2. Forensic-by-design cloud systems.
  3. Secure and tamper-evident logs.
  4. VM and storage snapshots.
  5. Tenant data segregation.
  6. Forensic responsibilities in SLAs.
  7. Forensic APIs for evidence collection.
  8. Staff training.
  9. Support for FaaS.

6. DFR vs CFR

7. Forensics-as-a-Service (FaaS)

FaaS is a cloud-based service that provides digital forensic capabilities on demand.

Services:

  1. Evidence acquisition.
  2. Evidence preservation.
  3. Indexing and searching.
  4. Evidence analysis.
  5. Reporting and case management.

8. Why FaaS Is Needed

  1. Large data volume: Handles terabytes of evidence.
  2. Data locality: Analyses data near its storage location.
  3. Specialized expertise: Provides access to specialist tools and skills.
  4. Cost efficiency: Reduces the need for expensive local infrastructure.
  5. Elastic scalability: Increases or decreases resources according to demand.

9. FaaS Architecture — Four Layers

  1. Infrastructure layer: Provides computing, storage and networking.
  2. Acquisition layer: Collects logs, memory captures and disk images.
  3. Processing layer: Performs hashing, indexing, searching and timeline reconstruction.
  4. Presentation and case-management layer: Displays results, generates reports and maintains records.

10. Security and Trust in FaaS

  1. Encrypt evidence in transit and at rest.
  2. Isolate each customer's evidence.
  3. Maintain immutable audit logs.
  4. Validate forensic tools.
  5. Define legal and jurisdictional responsibilities.
  6. Maintain chain of custody.

11. Representative FaaS Approaches

  1. Academic frameworks: Cloud-hosted evidence processing and automated analysis.
  2. Commercial extensions: Traditional tools such as EnCase and FTK use cloud-hosted processing.
  3. Cloud-native services: Providers offer integrated forensic and incident-response tools.

12. Parallel and Distributed Forensics

Parallel processing: Several tasks run simultaneously.

Distributed processing: Tasks are shared across multiple computers.

Benefits:

  1. Faster processing.
  2. Handles large evidence collections.
  3. Supports large-scale keyword searching.
  4. Speeds up hashing and indexing.
  5. Helps reconstruct timelines across many logs.

13. Key Techniques

  1. MapReduce/Hadoop: Divides tasks into smaller operations and combines results.
  2. Distributed indexing: Makes large evidence collections searchable.
  3. GPU acceleration: Speeds up suitable parallel tasks.
  4. Distributed network forensics: Analyses traffic from multiple collection points.
  5. Elastic clusters: Increase or decrease processing workers when needed.

14. FaaS Advantages and Challenges

Advantages:

  1. Scalable processing.
  2. Handles large datasets.
  3. Reduces hardware costs.
  4. Offers specialist tools.
  5. Supports faster investigations.

Challenges:

  1. Evidence confidentiality.
  2. Chain-of-custody requirements.
  3. Provider dependence.
  4. Legal and jurisdictional issues.
  5. Need for strong tenant isolation.
  6. Platform security and reliability.

Cloud Forensics — 17 Important Questions

How to write for 5+ marks: Start with the definition, explain the main points in order, add an example when possible, and finish with one concluding sentence. These answers are organised for exam revision.

1. Cloud-Based Attacks

Definition: Cloud-based attacks are cyberattacks that target cloud data, applications, accounts or infrastructure.

Types of cloud attacks:

  1. Phishing attack: Fake emails or websites trick users into revealing passwords.
  2. Password attack: Attackers try to guess or steal passwords.
  3. Malware attack: Malicious software damages systems or steals information.
  4. Data breach: Unauthorized people access confidential information.
  5. Insider attack: An employee or administrator misuses authorized access.
  6. Denial of Service (DoS): Excessive requests make a cloud service unavailable.
  7. API attack: Attackers exploit weaknesses in cloud application interfaces.
  8. VM escape attack: An attacker attempts to break out of a virtual machine's isolation.
  9. Co-tenant attack: An attacker targets another customer's resources in shared cloud infrastructure.
  10. Data loss attack: Important information is deleted, damaged or made unavailable.

Prevention:

  • Use strong passwords.
  • Enable Multi-Factor Authentication (MFA).
  • Encrypt sensitive data.
  • Apply access controls.
  • Update software regularly.
  • Monitor cloud activity.
  • Maintain secure backups.

Example: A hacker steals a cloud account password and downloads confidential company files.

2. Cryptographic Techniques

Definition: Cryptography protects information by converting it into a form that unauthorized people cannot easily understand.

Important techniques:

1. Symmetric encryption: Uses the same secret key for encryption and decryption.

  • Example: AES.
  • Advantage: Fast for large amounts of data.
  • Limitation: The secret key must be protected.

2. Asymmetric encryption: Uses a public key and a private key.

  • Examples: RSA and ECC.
  • Use: Secure key exchange and encryption.
  • Digital signatures use related public-private key mechanisms.

3. Hashing: Converts data into a fixed-length hash value.

  • Example: SHA-256.
  • Use: Checks data integrity.
  • A changed file normally produces a different hash.

4. Digital signature: Helps verify the signer's identity and whether signed data has changed.

  • Use: Authentication and integrity verification.

5. Convergent encryption: Derives an encryption key from the data.

  • Use: Allows identical files to have identical encrypted results for deduplication.
  • Limitation: Predictable data may be vulnerable to guessing attacks.

6. Searchable encryption: Allows certain searches over encrypted data.

  • Use: Searching cloud information without decrypting all the data.

7. Homomorphic encryption: Allows certain calculations on encrypted data.

  • Use: Privacy-preserving cloud computation.
  • Limitation: Can be computationally expensive.

Importance:

  • Protects confidentiality.
  • Helps verify integrity.
  • Supports authentication.
  • Protects data during storage and transmission.
  • Requires secure key management.

3. Importance of Cloud Forensics

Definition: Cloud forensics is the process of identifying, collecting, preserving, examining, analysing and presenting evidence from cloud systems.

Importance:

  1. Crime investigation: Helps investigate hacking, fraud and data theft.
  2. Evidence collection: Collects logs, files, snapshots and account records.
  3. Incident reconstruction: Determines what happened and when.
  4. User identification: Helps identify accounts involved in suspicious activities.
  5. Data recovery: Helps locate recoverable evidence where available.
  6. Security improvement: Identifies weaknesses in cloud systems.
  7. Legal support: Provides evidence for legal or disciplinary proceedings.
  8. Damage assessment: Identifies affected systems and information.
  9. Accountability: Helps determine which actions occurred and under which account.
  10. Compliance: Supports applicable legal and regulatory requirements.

Example: Investigating who accessed and deleted files from a cloud account.

5. Data Acquisition Techniques in Cloud Forensics

Definition: Data acquisition is the process of collecting digital evidence from cloud systems.

Techniques:

  1. Snapshot acquisition: Creates a point-in-time copy of a virtual machine disk or storage volume.
  2. API-based acquisition: Uses cloud APIs to collect logs, metadata and other available evidence.
  3. Live acquisition: Collects information from an active system, such as RAM, running processes and network state.
  4. Agent-based acquisition: Uses software agents to collect supported disk or memory information.
  5. Client-side acquisition: Collects evidence from a user's computer or mobile device, such as browser history and cached files.
  6. Provider-assisted acquisition: Obtains evidence from the Cloud Service Provider (CSP).
  7. Log acquisition: Collects login records, API activity, audit logs and access records.
  8. Network acquisition: Captures available network traffic for investigation.

Important steps:

  • Identify the evidence source.
  • Obtain proper authorization.
  • Select the correct acquisition method.
  • Preserve evidence before it disappears.
  • Calculate hash values where appropriate.
  • Record all collection activities.

Example: Taking a virtual machine snapshot before investigating a suspected attack.

6. Approaches Used for Cloud Digital Evidence Analysis

Definition: Cloud digital evidence analysis is the process of examining collected evidence to understand a security incident.

Main approaches:

1. Provider-side forensics

  • Collects evidence from the cloud provider.
  • Includes logs, snapshots and metadata.
  • Limitation: Depends on provider cooperation.

2. Client-side forensics

  • Examines the user's computer or mobile device.
  • Includes browser history, cached files and synchronized data.
  • Limitation: Shows only evidence available on that device.

3. Network forensics

  • Examines captured network traffic.
  • Helps identify suspicious connections and data transfers.
  • Limitation: Encryption may hide communication contents.

4. Hybrid approach

  • Combines provider-side, client-side and network evidence.
  • Compares information from different sources.
  • Provides a more complete investigation.

Analysis steps:

  • Organize collected evidence.
  • Search for suspicious activities.
  • Compare timestamps.
  • Verify integrity using hashes.
  • Reconstruct the event timeline.
  • Prepare a report.

Example: Comparing cloud login logs with browser history to investigate unauthorized access.

7. Importance of Forensic Readiness in Cloud

Definition: Forensic readiness is the ability to collect, preserve and analyse digital evidence when an incident occurs.

Importance:

  1. Early preparation: Makes systems ready for investigation.
  2. Evidence preservation: Prevents important evidence from disappearing.
  3. Reduced cost: Reduces investigation expenses.
  4. Faster investigation: Helps investigators start work quickly.
  5. Better evidence quality: Provides more complete and reliable information.
  6. Reduced disruption: Minimizes interruption to normal business.
  7. Legal support: Helps prepare evidence for legal proceedings.
  8. Compliance: Supports applicable regulations and organizational policies.
  9. Incident detection: Monitoring helps identify suspicious activity.
  10. Staff awareness: Trains employees to preserve evidence correctly.

How to achieve forensic readiness:

  • Enable audit logging.
  • Define evidence-retention policies.
  • Establish secure storage.
  • Prepare collection procedures.
  • Train staff.
  • Define responsibilities between the customer and CSP.

Example: Keeping cloud login logs so that a future security breach can be investigated.

8. Cloud-Based Forensics Service

Definition: A cloud-based forensic service provides digital investigation tools and resources through the cloud.

Forensics-as-a-Service (FaaS) is an example of this service model.

Main services:

  1. Evidence acquisition: Collects digital evidence.
  2. Evidence preservation: Protects evidence from unauthorized changes.
  3. Indexing: Organizes evidence for searching.
  4. Search: Finds relevant files and records.
  5. Evidence analysis: Examines data to identify suspicious activity.
  6. Reporting: Generates investigation reports.
  7. Case management: Organizes evidence and investigation records.

Advantages:

  • Reduces the need for expensive local infrastructure.
  • Provides scalable processing resources.
  • Handles large evidence collections.
  • Offers access to specialized tools.
  • Can reduce investigation time.
  • Supports remote collaboration.

Challenges:

  • Evidence confidentiality.
  • Dependence on the service provider.
  • Legal and jurisdictional issues.
  • Chain-of-custody requirements.
  • Risk of unauthorized access.

Example: An organization uses an online forensic service to search cloud logs for suspicious activity.

9. Components of a Cloud Forensics Readiness Framework

Definition: A Cloud Forensics Readiness (CFR) framework is a set of policies, technologies and procedures that prepares cloud systems for future investigations.

Main components:

  1. Shared responsibility: Defines the duties of the cloud customer and provider.
  2. Forensic-by-design: Configures systems to capture relevant events automatically.
  3. Immutable logging: Protects logs against unauthorized modification.
  4. Snapshotting: Preserves earlier states of virtual machines and storage.
  5. Data segregation: Separates one customer's evidence from other customers' data.
  6. Forensic SLAs: Define evidence retention, notification, cooperation and export responsibilities.
  7. Forensic APIs: Support snapshot creation, log export and evidence retrieval.
  8. Secure evidence storage: Protects collected evidence.
  9. Staff training: Prepares teams to handle evidence correctly.
  10. Evidence management: Maintains records of evidence handling and transfers.
  11. Monitoring: Detects incidents and records relevant activity.
  12. Legal policies: Ensure that collection and disclosure follow applicable laws.

Example: A cloud provider agrees to retain audit logs for a specified period and supply them through an approved process when an investigation is authorized.

10. Techniques for Data Deletion

Definition: Data deletion is the process of removing information from a storage system.

Main techniques:

  1. Logical deletion: Removes the file reference or marks its storage space as available.
  2. Overwriting: Writes new data over the old data.
  3. Secure erase: Uses supported storage commands to erase data.
  4. Cryptographic erasure: Destroys the necessary encryption keys to make encrypted data unreadable.
  5. Backup deletion: Removes relevant backup copies according to the retention and deletion policy.
  6. Snapshot deletion: Removes stored snapshots containing the data, where applicable.
  7. Physical destruction: Destroys the storage device itself; generally difficult for shared cloud infrastructure.

Cloud deletion challenges:

  • Data may have multiple copies.
  • Replicas may exist in different data centres.
  • Backups may retain old information.
  • Snapshots may contain previous versions.
  • Shared storage makes direct physical deletion difficult to verify.
  • Provider deletion procedures may take time.

Important point: Logical deletion does not guarantee permanent destruction. Actual deletion depends on the storage technology and provider's processes.

Example: Deleting a file from cloud storage may not immediately remove copies held in backups.

11. Hardware-Based and Software-Based Critical Modules

Definition: Hardware-based and software-based modules are components that help protect cloud systems, control access and support forensic investigations.

A. Hardware-based modules

  1. Hardware Security Module (HSM): A specialized device that securely manages cryptographic keys and performs cryptographic operations.
  2. Trusted Platform Module (TPM): A hardware component that supports security functions such as key protection and platform integrity checks.
  3. Physical servers: Provide computing resources for cloud services.
  4. Storage devices: Store cloud data and digital evidence.
  5. Network devices: Transfer data between computers and cloud systems.

  1. Logging module: Records user activities and system events.
  2. Access control module: Determines who can access cloud resources.
  3. Encryption module: Protects information from unauthorized reading.
  4. Hashing module: Calculates hash values to help verify data integrity.
  5. Monitoring module: Detects suspicious activities.
  6. Backup module: Creates copies of important data.
  7. Forensic analysis module: Examines files, logs and other digital evidence.
  8. Authentication module: Verifies the identity of users.

Importance:

  • Protects confidential information.
  • Prevents unauthorized access.
  • Helps detect attacks.
  • Supports evidence collection.
  • Helps verify evidence integrity.

Example: An HSM protects encryption keys, while logging software records who accessed a cloud resource.

12. Challenges in Cloud Forensics

Definition: Cloud forensic challenges are the difficulties investigators face when collecting, preserving and analysing evidence from cloud systems.

A. Technical challenges

  1. Loss of physical control: Investigators cannot normally access the provider's physical servers directly.
  2. Data location: Evidence may be stored across multiple data centres.
  3. Multi-tenancy: Multiple customers share the same physical infrastructure.
  4. Data volatility: Temporary logs, virtual machines and containers may disappear quickly.
  5. Encryption: Investigators may not have the keys needed to read encrypted data.
  6. Large data volume: Huge amounts of evidence are difficult to analyse manually.
  7. Data replication: Multiple copies make it difficult to identify and preserve all relevant evidence.
  8. Evidence integrity: Investigators must demonstrate that evidence has not been altered.

B. Organizational challenges

  1. Provider dependence: Investigators may depend on the CSP for evidence.
  2. Lack of standard procedures: Providers may use different evidence-collection methods.
  3. Unclear SLAs: Contracts may not define forensic responsibilities clearly.
  4. Lack of expertise: Skilled cloud forensic investigators may be limited.

C. Legal challenges

  1. Jurisdiction: Different countries have different laws.
  2. Privacy: Laws may restrict access to personal information.
  3. Data sovereignty: Some data is subject to rules concerning where it is stored.
  4. Chain of custody: Evidence passes through different organizations.
  5. Tenant privacy: Investigators must avoid exposing other customers' data.

Conclusion: Cloud forensic challenges require proper planning, provider cooperation, secure evidence handling and compliance with applicable laws.

17. Parallel and Distributed Processing Techniques in Forensic Analysis

Definition: Parallel and distributed processing are methods used to process large amounts of digital evidence efficiently.

A. Parallel processing

Definition: Parallel processing performs multiple tasks simultaneously using multiple processing units or cores.

Example: Checking the hashes of several files at the same time.

Advantages:

  • Reduces processing time.
  • Speeds up repetitive tasks.
  • Improves processing efficiency.

B. Distributed processing

Definition: Distributed processing divides a large task among multiple computers and combines their results.

Example: Dividing millions of cloud log records among several computers for analysis.

Advantages:

  • Handles large datasets.
  • Uses multiple computers.
  • Improves processing speed.
  • Supports large-scale investigations.

C. Important techniques

1. MapReduce and Hadoop

  • Divides large tasks into smaller operations.
  • The Map stage processes separate portions of data.
  • The Reduce stage combines the results.
  • Used for hashing, indexing and evidence extraction.

2. Distributed indexing

  • Organizes large evidence collections into searchable indexes.
  • Helps investigators find information quickly.
  • Technologies such as Elasticsearch support searching across large datasets.

3. GPU acceleration

  • Uses Graphics Processing Units to perform suitable calculations in parallel.
  • Can accelerate hashing, password recovery and image classification.
  • Performance depends on the task and implementation.

4. Distributed network forensics

  • Collects or analyses network traffic at multiple points.
  • Combines the results to understand cloud network activity.

5. Elastic cloud clusters

  • Add processing workers when more computing power is required.
  • Reduce resources when processing finishes.
  • Help control resource usage and cost.

D. Importance in cloud forensics

  1. Processes large amounts of evidence.
  2. Speeds up keyword searching.
  3. Accelerates file hashing and indexing.
  4. Helps reconstruct timelines from many logs.
  5. Supports large cloud investigations.
  6. Enables scalable Forensics-as-a-Service platforms.

Conclusion: Parallel and distributed processing help investigators analyse large cloud evidence collections faster than relying only on sequential processing on a single computer.
