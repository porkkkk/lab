1. Network Reconnaissance, Security Logs & TTL

Aim: Find public domain/DNS information, review important security logs and understand TTL.

Algorithm

  1. Open a terminal and run domain lookup commands.
  2. Record IP/DNS details and route output.
  3. Review security event IDs.
  4. Check Google DNS TTL using dig.

Linux commands

whois stc.ac.in
dig stc.ac.in
nslookup stc.ac.in
dig +short stc.ac.in
traceroute stc.ac.in
ping -c 1 google.com
dig google.com

Install required tools

sudo apt update
sudo apt install whois traceroute dnsutils -y

Windows Event Viewer

eventvwr.msc

Event ID 4624 = Successful login
Event ID 4625 = Failed login
Event ID 4720 = User account created
Event ID 4726 = User account deleted
Event ID 1102  = Security audit log cleared
Remember: WHOIS = domain details; dig/nslookup = DNS; traceroute = hops. IP packet TTL limits router hops. DNS TTL is a cache duration in seconds and changes over time.

2. Detect MAC / ARP Changes Using ARPwatch

Aim: Monitor IP-to-MAC address mapping changes in an authorized lab.

Algorithm

  1. Install ARPwatch.
  2. Start the service.
  3. Check logs for unexpected changes.
  4. Investigate before concluding spoofing occurred.

Commands

sudo apt update
sudo apt install arpwatch -y
ip addr
ip route
sudo systemctl enable --now arpwatch
sudo systemctl status arpwatch
sudo journalctl -u arpwatch
An IP-to-MAC change is a warning to investigate, not proof of spoofing.

4. Buffer Overflow Concept Using C

Aim: Understand buffer boundaries with a safe input example.

Algorithm

  1. Create a character array.
  2. Read bounded input.
  3. Print the value.
  4. Compile and run.

buffer.c

#include <stdio.h>

int main(void) {
    char name[20];

    printf("Enter your name: ");
    if (scanf("%19s", name) != 1) {
        return 1;
    }

    printf("Your name is %s\\n", name);
    return 0;
}

Compile and run

gcc buffer.c -o buffer
./buffer
Remember: Buffer overflow means writing beyond allocated memory. `%19s` limits input to fit in `char name[20]` including the string terminator.

5. Find Website IP and Total Hops

Aim: Resolve the IP and count the hops reported for Microsoft and the college website.

Algorithm

  1. Resolve the hostname.
  2. Run traceroute/tracert.
  3. Count responding hop lines and record the results.

Linux

nslookup www.microsoft.com
traceroute www.microsoft.com
nslookup stc.ac.in
traceroute stc.ac.in

Windows

nslookup www.microsoft.com
tracert www.microsoft.com

IP addresses and hop counts can change. Some routers do not reply, so record your actual lab output.

6. Block and Unblock TCP Port 8080

Aim: Add a firewall block rule, verify it, remove it, and verify removal.

Algorithm

  1. Insert the DROP rule.
  2. Check that the rule exists.
  3. Delete the rule.
  4. Check that the rule no longer exists.

Block port 8080

sudo iptables -I INPUT 1 -p tcp --dport 8080 -j DROP
sudo iptables -L INPUT -n -v --line-numbers

Verify rule exists (exit code 0 = found)

sudo iptables -C INPUT -p tcp --dport 8080 -j DROP
echo $?

Unblock and verify (exit code 1 = rule not found)

sudo iptables -D INPUT -p tcp --dport 8080 -j DROP
sudo iptables -C INPUT -p tcp --dport 8080 -j DROP
echo $?
Run on your own lab machine. Firewall changes apply immediately and can affect connections. Removing this rule does not guarantee the port is reachable if other rules or services affect it.

7. Snort IDS Rule, Test and Removal

Aim: Install Snort, add a simple ICMP alert rule, observe results and uninstall.

Algorithm

  1. Install and check Snort.
  2. Create a custom rule file.
  3. Run Snort on the correct lab interface.
  4. Generate test traffic and inspect alerts.
  5. Uninstall Snort if required.

Install and inspect

sudo apt update
sudo apt install snort -y
snort -V
ip link
ls /etc/snort

Create rule file

alert icmp any any -> any any (msg:"ICMP TEST ALERT"; sid:1000001; rev:1;)

Run in a compatible Snort 3 installation

nano ~/test.rules
sudo snort -c /etc/snort/snort.lua -R ~/test.rules -i eth0 -A alert_fast
ping -c 4 8.8.8.8

Uninstall

sudo apt purge snort -y
sudo apt autoremove -y
Replace eth0 with your actual interface. Snort version/configuration paths differ; use the installed version's configuration. The ICMP rule alerts only on traffic visible to the selected interface.

8. College Domain Details

Aim: Gather available public registration and DNS records for the college domain.

Algorithm

  1. Check domain registration.
  2. Query A and AAAA records.
  3. Query name servers and mail servers.
  4. Record available results.

Commands

whois stc.ac.in
dig stc.ac.in
dig +short stc.ac.in
dig A stc.ac.in
dig AAAA stc.ac.in
dig NS stc.ac.in
dig MX stc.ac.in
nslookup stc.ac.in
Remember: WHOIS = registration; A = IPv4; AAAA = IPv6; NS = name servers; MX = mail servers.

9. Vulnerability Assessment Using OWASP ZAP

Aim: Assess a local training web application and review possible vulnerabilities.

Algorithm

  1. Install/open ZAP.
  2. Run a local training application.
  3. Set the target in ZAP.
  4. Scan and review alerts.
  5. Write findings and suggested fixes.

Install ZAP on supported Debian/Ubuntu systems

sudo apt update
sudo apt install zaproxy -y
zaproxy

Optional local OWASP Juice Shop with Docker

sudo apt install docker.io -y
sudo systemctl start docker
sudo docker pull bkimminich/juice-shop
sudo docker run --rm -p 127.0.0.1:3000:3000 bkimminich/juice-shop

Test local app

curl http://127.0.0.1:3000

Open http://127.0.0.1:3000 in your browser, then browse/scan that local URL in ZAP. Keep the Docker terminal running.

Scan only systems you own or have permission to test. Keep the deliberately vulnerable Juice Shop bound to localhost.
