UNIT I

Overview of Java, Data Types, Arrays & Control Statements

Basics

1. Introduction to Java

Definition: Java is a high-level, object-oriented programming language. It was developed by James Gosling at Sun Microsystems. Java programs run using the Java Virtual Machine (JVM).
  • Simple: Java syntax is easy to learn compared with many older languages.
  • Object-oriented: Programs use classes and objects.
  • Platform-independent: Bytecode can run on systems with a JVM.
  • Secure: Java provides bytecode verification and controlled memory access.
  • Robust: Exception handling helps manage errors.
  • Multithreaded: It can perform more than one task at a time.
  • Portable: Java bytecode can be moved between supported systems.
Remember: WORA = Write Once, Run Anywhere. javac compiles .java into bytecode (.class); JVM runs the bytecode.

4. Arrays

An array stores multiple values of the same data type using one variable name. Array size is fixed after creation and elements are accessed by index starting at 0.
class ArrayDemo {
  public static void main(String[] args) {
    int[] marks = {80, 90, 75};
    for (int i = 0; i < marks.length; i++) {
      System.out.println(marks[i]);
    }
  }
}

Output: 80, 90, 75 (each on a new line). Types: one-dimensional and multidimensional arrays.

8. Program: Largest of Three Numbers (if-else)

class Largest {
  public static void main(String[] args) {
    int a = 10, b = 25, c = 15;
    if (a >= b && a >= c)
      System.out.println("Largest = " + a);
    else if (b >= a && b >= c)
      System.out.println("Largest = " + b);
    else
      System.out.println("Largest = " + c);
  }
}

Output: Largest = 25. Explanation: if checks whether a is largest; else-if checks b; otherwise c is largest.

UNIT II

Classes, Objects, Methods, Constructors & Inheritance

OOP coding

1. Class and Object

Class: A blueprint or design used to create objects. It contains variables and methods. Object: An instance of a class with its own data.
  • Class defines the structure.
  • Variables store data (state).
  • Methods perform actions (behaviour).
  • One class can create many objects.
class Student {
  int mark;
  void display() {
    System.out.println(mark);
  }
}
class Demo {
  public static void main(String[] args) {
    Student s = new Student();
    s.mark = 90;
    s.display();
  }
}

2. Declaring Objects and Reference Variables

Student s;              // reference declaration
s = new Student();      // object creation
Student t = s;          // reference assignment

Important: new creates an object in memory. A reference variable stores the reference to that object. After t = s, both refer to the same object; a second object is not created.

3. Methods

A method is a named block of code that performs one task. It supports code reuse and modular programming.
int add(int a, int b) {
  return a + b;
}

void means the method returns no value. return sends a result back to the caller.

4. Constructors and Constructor Overloading

A constructor is a special member used to initialize an object. Its name is the same as the class name and it has no return type. It runs automatically when an object is created using new.
  • Default constructor: No parameters. If no constructor is written, Java supplies a default constructor.
  • Parameterized constructor: Receives values to initialize an object.
  • Constructor overloading: More than one constructor with different parameter lists.
class Student {
  int mark;
  Student() {
    mark = 0;
  }
  Student(int m) {
    mark = m;
  }
  void show() {
    System.out.println(mark);
  }
}
class Demo {
  public static void main(String[] args) {
    Student a = new Student();
    Student b = new Student(90);
    a.show();
    b.show();
  }
}

Output: 0 then 90.

5. this Keyword

this refers to the current object. It is commonly used when a parameter name and an instance-variable name are the same.
class Student {
  int mark;
  Student(int mark) {
    this.mark = mark;
  }
  void show() {
    System.out.println(this.mark);
  }
}

Here this.mark means the object's variable; mark means the constructor parameter.

7. Inheritance

Inheritance is the process in which one class gets accessible fields and methods from another class. It improves code reuse.
  • Parent class is also called superclass.
  • Child class is also called subclass.
  • Use extends for class inheritance.
  • Java supports single, multilevel and hierarchical class inheritance.
  • Multiple inheritance of classes is not supported directly; interfaces provide multiple inheritance of type.
class Animal {
  void eat() {
    System.out.println("Eating");
  }
}
class Dog extends Animal {
  void bark() {
    System.out.println("Barking");
  }
}
class Demo {
  public static void main(String[] args) {
    Dog d = new Dog();
    d.eat();
    d.bark();
  }
}

Output: Eating / Barking.

UNIT III

Packages, Member Access, Interfaces & Exception Handling

Very important

1. Package

A package is a group of related classes and interfaces. It organizes programs, avoids name conflicts and controls access.
  • Write package packname; as the first statement.
  • Package names normally match folder names.
  • Built-in packages include java.lang, java.util, java.io, java.awt and javax.swing.
  • User-defined packages are created by programmers.

2. Creating and Importing a Package

// File: pack1/Message.java
package pack1;
public class Message {
  public void show() {
    System.out.println("Hello Package");
  }
}

// File: Test.java
import pack1.Message;
class Test {
  public static void main(String[] args) {
    Message m = new Message();
    m.show();
  }
}

Compile from the parent folder: javac pack1/Message.java, then javac Test.java; run using java Test.

3. Member Access / Access Modifiers

Access modifiers decide where a class member (variable or method) can be used.

Default access: If no access modifier is written, the member can be accessed only inside the same package. It is also called package-private.

4. Interface

An interface is a contract that tells a class which methods it must provide. A class uses the implements keyword.
  • It supports abstraction.
  • A class can implement more than one interface.
  • Interface fields are public, static and final by default.
  • Traditional abstract interface methods are public and abstract by default.
  • Interfaces can be used to achieve multiple inheritance of type.
interface Printable {
  void print();
}
interface Showable {
  void show();
}
class Demo implements Printable, Showable {
  public void print() {
    System.out.println("Print");
  }
  public void show() {
    System.out.println("Show");
  }
  public static void main(String[] args) {
    Demo d = new Demo();
    d.print();
    d.show();
  }
}

Output: Print / Show.

5. Exception Handling

An exception is an abnormal event or runtime problem that interrupts the normal flow of a program. Exception handling manages the problem without an uncontrolled program stop.
  • try: Contains code that may cause an exception.
  • catch: Handles the exception.
  • finally: Runs after try/catch in normal completion paths; commonly used to release resources.
  • throw: Manually throws an exception.
  • throws: Declares that a method may pass an exception to its caller.
class ExceptionDemo {
  public static void main(String[] args) {
    try {
      int a = 10 / 0;
    }
    catch (ArithmeticException e) {
      System.out.println("Cannot divide by zero");
    }
    finally {
      System.out.println("Program completed");
    }
  }
}

Output: Cannot divide by zero / Program completed.

7. Multiple catch blocks

try {
  int n = 10 / 0;
}
catch (ArithmeticException e) {
  System.out.println("Math error");
}
catch (Exception e) {
  System.out.println("Other error");
}

Only the first matching catch runs. Put specific exception catches before general catches such as Exception.

UNIT IV

Multithreading, Files, Streams & String Handling

Programs likely

1. Thread and Multithreading

A thread is a small independent path of execution inside a program. Multithreading means running two or more threads concurrently in one program.
  • Improves CPU use and responsiveness.
  • Threads share the same process memory.
  • Useful for file operations, network tasks and user interfaces.
  • Threads are lighter than separate processes.

2. Creating a Thread using Runnable

  1. Create a class that implements Runnable.
  2. Write the task inside run().
  3. Create a Thread object and pass the Runnable object.
  4. Call start() to begin a new thread.
class MyTask implements Runnable {
  public void run() {
    System.out.println("Thread is running");
  }
}
class Demo {
  public static void main(String[] args) {
    MyTask task = new MyTask();
    Thread t = new Thread(task);
    t.start();
  }
}

Output: Thread is running.

Remember: start() starts a new thread and then the JVM calls run(). Calling run() directly is just a normal method call.

3. Thread Life Cycle

  1. New: Thread object is created.
  2. Runnable: start() is called; thread is ready or running under scheduler control.
  3. Blocked / Waiting / Timed Waiting: Thread temporarily cannot continue (for example, waiting for a lock or sleep time).
  4. Terminated: run() finishes or the thread ends.

Simple diagram to draw: New → Runnable → Running → Waiting/Blocked → Runnable → Terminated. Java's official state names group ready and running under RUNNABLE.

5. Synchronization

Synchronization controls access to shared data. A synchronized method allows only one thread at a time to execute it on the same object.
  • Prevents race conditions.
  • Protects shared data from mixed or incorrect updates.
  • Uses an object's lock/monitor.
synchronized void withdraw(int amount) {
  balance = balance - amount;
}

6. Files and Java I/O

A file stores data permanently. Java I/O classes read data from a source and write data to a destination. Many of these classes are in java.io.

Common file operations: create, read, write, append, close and delete.

8. Program: Read a Text File using FileReader

import java.io.FileReader;
import java.io.IOException;

class ReadFile {
  public static void main(String[] args) {
    try {
      FileReader r = new FileReader("data.txt");
      int ch;
      while ((ch = r.read()) != -1) {
        System.out.print((char) ch);
      }
      r.close();
    }
    catch (IOException e) {
      System.out.println("File error");
    }
  }
}

Place data.txt in the program's working directory. read() returns -1 when the end of the file is reached. close() closes the file.

UNIT V

AWT, Events, Swing Components & MVC

GUI

1. AWT

AWT means Abstract Window Toolkit. It is Java's original GUI toolkit, used to create windows, buttons, labels, text fields, menus and graphics. AWT classes are mainly in java.awt.
  • Component is the base class for visual controls.
  • Container holds other components.
  • Frame creates a normal application window.
  • Panel groups components.
  • Layout managers arrange components.

3. Event Delegation Model

The event delegation model is Java's way of handling user actions. An event source creates an event and sends it to a registered listener.
  1. Event source: Component where action happens, such as Button.
  2. Event object: Contains details about the action, such as ActionEvent.
  3. Event listener: Object that waits for and handles the event, such as ActionListener.
  4. Register listener using addActionListener().
  5. Write handling code inside actionPerformed().
import java.awt.*;
import java.awt.event.*;

class EventDemo extends Frame implements ActionListener {
  Button b;
  EventDemo() {
    b = new Button("Click");
    add(b);
    b.addActionListener(this);
    setSize(250, 150);
    setVisible(true);
  }
  public void actionPerformed(ActionEvent e) {
    System.out.println("Button clicked");
  }
  public static void main(String[] args) {
    new EventDemo();
  }
}

4. Swing

Swing is a Java GUI toolkit built on top of AWT. It provides richer, lightweight and more customizable components. Most Swing component names start with J.

Swing classes are mainly in javax.swing. Event handling classes are commonly in java.awt.event.

6. Login Form using Swing

import javax.swing.*;
import java.awt.*;
import java.awt.event.*;

class Login extends JFrame implements ActionListener {
  JTextField user;
  JPasswordField pass;
  JButton login;
  JLabel result;

  Login() {
    setTitle("Login Form");
    setLayout(new FlowLayout());
    add(new JLabel("Username:"));
    user = new JTextField(15);
    add(user);
    add(new JLabel("Password:"));
    pass = new JPasswordField(15);
    add(pass);
    login = new JButton("Login");
    add(login);
    result = new JLabel("");
    add(result);
    login.addActionListener(this);
    setSize(250, 200);
    setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
    setVisible(true);
  }

  public void actionPerformed(ActionEvent e) {
    if (user.getText().equals("admin") &&
        new String(pass.getPassword()).equals("1234"))
      result.setText("Login successful");
    else
      result.setText("Invalid login");
  }

  public static void main(String[] args) {
    new Login();
  }
}

Note: This is a simple classroom demonstration only; real applications should not store passwords in plain text.

8. MVC Architecture

MVC means Model–View–Controller. It divides a GUI component into three parts so that data, appearance and user-action handling are organized separately.
  • Model: Stores data or state. Example: whether a checkbox is selected.
  • View: Displays the component on screen.
  • Controller: Handles user actions and updates the model.

Working: User clicks a checkbox → Controller receives the action → Model state changes → View displays the updated state.

Memory trick: Model = Data, View = Display, Controller = Action.
