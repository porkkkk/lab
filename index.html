01. Network reconnaissance

WHOIS · DNS · security logs · TTL · traceroute

Aim: To collect public website information, inspect security warnings, and check network hops.

Algorithm — LOOK → CHECK → WRITE

  1. Open Terminal or Command Prompt.
  2. Look up domain and DNS information.
  3. Check the route and ping response.
  4. Open security logs and note critical warnings.
  5. Write only results you actually observe.

Linux

whois stc.ac.in
dig stc.ac.in
traceroute www.microsoft.com
traceroute stc.ac.in
ping -c 4 google.com

Windows

nslookup stc.ac.in
tracert www.microsoft.com
tracert stc.ac.in
ping google.com
ipconfig

TTL and critical warnings

TTL means Time To Live. For IP packets it limits the number of router hops. The TTL shown by a ping reply is the observed reply TTL, not necessarily the original value.

Security-log warnings to investigate include repeated failed logins, unexpected account creation, audit-log clearing, unknown startup programs, and unexpected privilege changes.

Remember: WHOIS = domain details · DNS = records · traceroute = hops · ping = reachability · TTL = hop limit.

02. Detect ARP spoofing with ARPwatch

Aim: To monitor IP-to-MAC address changes and investigate unusual changes.

Algorithm — INSTALL → START → CHECK

  1. Install ARPwatch and the log service.
  2. Find your real network interface.
  3. Start ARPwatch for that interface.
  4. Read logs and verify any alerts.
sudo apt update
sudo apt install arpwatch rsyslog -y
sudo systemctl enable --now rsyslog
ip link show

# Replace eth0 with your real interface
sudo systemctl enable --now arpwatch@eth0.service
sudo systemctl status arpwatch@eth0.service
sudo grep -i arpwatch /var/log/syslog
Remember: ARPwatch watches IP ↔ MAC changes. A change is a warning to investigate, not proof by itself.

04. Buffer overflow — simple safe C program

Aim: To understand that a buffer has a fixed size and input must not exceed it.

Algorithm — INPUT → CHECK → DISPLAY

  1. Create a character array of 20 spaces/bytes.
  2. Read the input safely with fgets().
  3. Remove the newline if present.
  4. Display the entered text.
// buffer.c — simple, safe demonstration
#include 

int main() {
    char name[20];

    printf("Enter name: ");
    scanf("%19s", name);

    printf("Name: %s", name);

    return 0;
}

Compile and run

gcc buffer.c -o buffer
./buffer
Simple explanation: Buffer overflow happens when a program writes more data into a buffer than it can hold. Here, name[20] holds at most 19 typed characters plus the ending \\0. fgets() limits the input and demonstrates the safe method.

This is a safe memory-safety demonstration, not an exploit that corrupts memory. For the practical record, explain the overflow risk and show how bounded input prevents it.

05. Block and unblock port 8080

Aim: To block TCP port 8080, verify the rule, then remove the rule to unblock it.

Algorithm — BLOCK → VERIFY → UNBLOCK

  1. List firewall rules.
  2. Add a rule blocking inbound TCP port 8080.
  3. Verify the rule exists.
  4. Delete the exact rule to unblock.
  5. List rules again to confirm removal.
# Linux lab machine; use only if you administer it
sudo iptables -I INPUT -p tcp --dport 8080 -j DROP

# Prove the rule is present
sudo iptables -L INPUT -n -v --line-numbers

# Unblock by deleting the matching rule
sudo iptables -D INPUT -p tcp --dport 8080 -j DROP

# Prove the rule is gone
sudo iptables -L INPUT -n -v --line-numbers
Remember: DROP = block. Delete the same rule = unblock. A firewall rule listing proves the rule is configured; test actual port access only against your own lab service.
Do not change firewall rules on a shared/college machine or over a remote connection unless your instructor has approved it.

06. Snort: detect traffic and remove the tool

Aim: To install Snort, check its version, validate the matching configuration, and remove it from a personal lab system if instructed.

Algorithm — INSTALL → CHECK → TEST → REMOVE

  1. Update package lists and install Snort.
  2. Check the installed version.
  3. Check which configuration file exists.
  4. Test using version-appropriate options.
  5. Remove only from your own lab machine if asked.
sudo apt update
sudo apt install snort -y
snort -V
ls /etc/snort

# Snort 3 only, if snort.lua exists
sudo snort -T -c /etc/snort/snort.lua

# Remove from your own lab computer only
sudo apt purge snort -y
sudo apt autoremove -y
Remember: Snort = IDS (Intrusion Detection System). It inspects traffic and can generate alerts. Snort 2 and 3 commands differ.

07. College domain details

Aim: To collect domain registration and DNS information using suitable lookup tools.

Algorithm — DOMAIN → DNS → RECORD

  1. Run WHOIS for domain registration information.
  2. Run DNS lookup for IP and name-server records.
  3. Record the actual output and lookup date.
whois stc.ac.in
nslookup stc.ac.in
nslookup -type=NS stc.ac.in
nslookup -type=MX stc.ac.in

# Linux, if dig is installed
dig stc.ac.in A
dig stc.ac.in NS
dig stc.ac.in MX
Remember: WHOIS = registration; A = IPv4 address; NS = name servers; MX = mail servers. DNS output may change over time.

08. Vulnerability assessment using OWASP ZAP

Aim: To scan a web application and record security alerts with suggested fixes.

Algorithm — OPEN → SCAN → REPORT

  1. Install and open OWASP ZAP.
  2. Use a local training app or an explicitly approved target.
  3. Browse through ZAP and review passive alerts first.
  4. Run active scan only with permission.
  5. Record alert name, risk, evidence, and remediation.
# Optional: install ZAP if available in your distro
sudo apt update
sudo apt install zaproxy -y
zaproxy

# Optional local training target using Docker
sudo apt install docker.io -y
sudo systemctl enable --now docker
sudo docker pull bkimminich/juice-shop
sudo docker run --rm -p 127.0.0.1:3000:3000 bkimminich/juice-shop

# In another terminal
curl http://127.0.0.1:3000
Remember: ZAP = web app scanner. Alert → risk → evidence → fix. Localhost keeps the practice app on your own computer.
