1.Explain variables, assignment statements and arithmetic operations in Python.

Meaning of variable

A variable is a name used to store a value in a program. Python creates a variable when we assign a value to it.

Rules for variable names

  • A name can contain letters, numbers and underscore (_).
  • It must not start with a number.
  • Spaces and special symbols are not allowed.
  • Python keywords cannot be used as variable names.
  • Names are case-sensitive: age and Age are different.

Assignment statement

The = symbol assigns a value to a variable.

name = "Ravi"
age = 20
mark = 85.5

Arithmetic operators

  • + Addition — adds two values.
  • - Subtraction — finds the difference.
  • * Multiplication — multiplies values.
  • / Division — gives a decimal result.
  • // Floor division — gives the whole-number quotient.
  • % Modulus — gives the remainder.
  • ** Power — raises a number to a power.
a = 10
b = 3
print(a + b)   # 13
print(a - b)   # 7
print(a * b)   # 30
print(a / b)   # 3.333...
print(a // b)  # 3
print(a % b)   # 1
print(a ** b)  # 1000

Conclusion: Variables store data, assignment gives values to variables, and arithmetic operators perform calculations.

3.Explain different types of strings in Python.

A string is a group of characters written inside quotation marks. Strings are used to store text.

Types / ways of writing strings

  • Single-quoted: text inside one pair of single quotes.
  • Double-quoted: text inside double quotes.
  • Triple-quoted: uses three single or double quotes; useful for multi-line text.
  • Raw string: starts with r; backslashes are treated mostly as normal characters, useful for paths and patterns.
  • Formatted string (f-string): starts with f; allows variables inside braces.
a = 'Hello'
b = "Python"
c = """This is
a multi-line string"""
path = r"C:\Users\Student"
name = "Anu"
message = f"Welcome {name}"
print(a, b, c, path, message)

Strings are immutable, which means their characters cannot be changed directly after creation.

4.Explain control statements in Python.

Control statements decide the order in which program instructions run. They help a program make decisions and repeat work.

1. Conditional statements

if, elif and else run code based on a condition.

mark = 75
if mark >= 50:
    print("Pass")
else:
    print("Fail")

2. Looping statements

  • for loop repeats over a sequence or range.
  • while loop repeats while a condition is true.
for i in range(1, 4):
    print(i)

count = 1
while count <= 3:
    print(count)
    count += 1

3. Jump statements

  • break stops the loop.
  • continue skips the current round and moves to the next.
  • pass does nothing; it is used as a placeholder.

Conclusion: Control statements help Python choose, repeat and control program actions.

6.Explain break and continue statements with examples.

break and continue are loop-control statements.

break

It immediately stops the nearest loop. Program execution continues after the loop.

for n in range(1, 6):
    if n == 4:
        break
    print(n)
# Output: 1 2 3

continue

It skips the remaining statements in the current round and starts the next round.

for n in range(1, 6):
    if n == 3:
        continue
    print(n)
# Output: 1 2 4 5

Difference

  • break ends the loop completely.
  • continue skips only one round.

Conclusion: Both statements control loop execution, but they work differently.

9.Explain recursion with an example.

Recursion is a process in which a function calls itself to solve a smaller part of a problem.

Important parts

  • Base condition: stops the function from calling itself forever.
  • Recursive call: calls the same function with a smaller or simpler value.

Example — factorial

def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)

print(factorial(5))  # Answer: 120

Working: factorial(5) becomes 5 × 4 × 3 × 2 × 1 = 120. The base condition is n == 0.

Advantages and care

  • Useful for problems that can be divided into smaller similar problems.
  • Can make some programs easy to understand.
  • A missing base condition can cause infinite recursion.

11.Explain sequence slicing and unpacking with examples.

Slicing means taking a part of a sequence such as a string, list or tuple.

Slicing syntax

sequence[start : stop : step]
  • start is the starting index (included).
  • stop is the ending index (not included).
  • step tells how many positions to move.
numbers = [10, 20, 30, 40, 50]
print(numbers[1:4])  # [20, 30, 40]
print(numbers[:3])   # [10, 20, 30]
print(numbers[::2])  # [10, 30, 50]

Unpacking

Unpacking assigns sequence items to separate variables.

student = ("Ravi", 20, "DCFS")
name, age, course = student
print(name)
print(age)
print(course)

The number of variables should normally match the number of items. Slicing gets selected items; unpacking separates items into variables.

12.Explain list comprehension with an example.

List comprehension is a short way to create a new list from an existing sequence. It can also include a condition.

Syntax

new_list = [expression for item in sequence if condition]

Example 1 — squares

squares = []
for number in range(1, 6):
    squares.append(number * number)

print(squares)
# Answer: [1, 4, 9, 16, 25]

Example 2 — even numbers

even = []
for number in range(1, 11):
    if number % 2 == 0:
        even.append(number)

print(even)
# Answer: [2, 4, 6, 8, 10]

Advantages

  • Uses fewer lines of code.
  • Easy to create lists.
  • Can filter values using a condition.

16.Explain string comparison and substring searching.

String comparison checks whether two strings are equal or which one comes first. Python compares strings character by character using Unicode values.

Comparison operators

  • == checks whether strings are equal.
  • != checks whether they are different.
  • < and > compare their order.

Substring searching

  • in checks whether a smaller string is present.
  • find() returns the position of the first match, or -1 if not found.
  • count() counts occurrences.
text = "python programming"
print("python" in text)       # True
print(text.find("program"))  # 7
print(text.count("m"))       # 2
print("Python" == "python")  # False

String comparisons are case-sensitive. Convert both strings to lowercase when a case-insensitive comparison is needed.

17.Explain string splitting and joining with examples.

Splitting divides one string into a list of smaller strings. The split() method is used.

20.Explain how to detect suspicious logon scripts.

A suspicious logon script is an unexpected or changed script that runs when a user signs in. It may try to collect information, change settings or run unknown programs.

Detection steps

  1. List the scripts configured for user logon.
  2. Check the file location and file owner.
  3. Compare the script with an approved copy or known hash.
  4. Look for unknown commands, encoded text or unexpected downloads.
  5. Check file creation and modification times.
  6. Review security and logon event logs.
  7. Scan the file with updated security software.
  8. Disable or isolate a suspicious entry only after following the organisation's response process.

Warning signs

  • A script appears unexpectedly.
  • Its name imitates a trusted system file.
  • It runs from a temporary or user-writable folder.
  • It makes unusual network connections.
  • It was modified without approval.

Conclusion: Regular checks, file integrity monitoring and event-log review help identify suspicious logon scripts.

21.Explain execution-flow hijacking.

Execution-flow hijacking is an attack in which an attacker changes the normal path of a program so that unintended code runs. It can happen when a system trusts unsafe files, libraries or program paths.

Common forms

  • DLL search-order hijacking: a program loads an unsafe library instead of the correct one.
  • Path hijacking: a program finds an untrusted executable because of an unsafe search path.
  • Unquoted service path issue: a poorly configured Windows service path may be interpreted incorrectly.
  • Unsafe plugin loading: a program loads an untrusted plugin.

Security impact

  • Unwanted code may run under the program's permissions.
  • Data or system settings may be affected.
  • It may help an attacker maintain access.

Prevention

  • Use trusted, absolute paths.
  • Restrict write permissions on program and library folders.
  • Keep software updated.
  • Use code signing and application control.
  • Monitor unexpected child processes and library loads.

Conclusion: Secure paths, permissions and monitoring reduce execution-flow hijacking risks.

22.Explain how to detect suspicious Python libraries.

A Python library is reusable code that can be added to a program. A suspicious library may be fake, modified or downloaded from an untrusted source.

Detection methods

  1. Install packages only from trusted sources.
  2. Check the package name carefully for spelling mistakes or look-alike names.
  3. Review the author, project page, release history and community activity.
  4. Check dependencies and requested permissions.
  5. Compare installed package versions with the approved requirements file.
  6. Use hash checks or software-composition analysis tools.
  7. Scan source code and monitor unexpected file or network activity.

Useful commands

python -m pip list
python -m pip show package_name
python -m pip check
python -m pip freeze

Conclusion: Trusted sources, package review, version control and security scanning help detect unsafe Python libraries.

Warning signs

24.Explain Alternate Data Streams (ADS) and their detection.

Alternate Data Streams (ADS) are an NTFS file-system feature in Windows. A file can contain an additional named data stream besides its main content. This feature has valid uses, but attackers may misuse it to hide data.

Risks

  • Extra data may not be visible in normal file browsing.
  • Malicious content may be hidden in an alternate stream.
  • It can make investigation more difficult.

Detection

  • Use trusted forensic tools that can list NTFS streams.
  • Review unexpected streams attached to ordinary files.
  • Compare stream names, sizes and timestamps with normal system activity.
  • Scan suspicious content safely in an isolated environment.
  • Preserve forensic evidence before making changes.

Example command for authorised checking

dir /r

This Windows command can display alternate data streams. Do not delete a stream just because it is unfamiliar; first verify whether it is legitimate.

Conclusion: ADS is a normal NTFS feature, but stream inspection is important during security investigations.

25.Explain how to protect passwords stored in web browsers.

Browsers can save usernames and passwords to make login easier. If a device or browser account is compromised, saved passwords may be exposed.

Protection methods

  1. Use a strong device password or PIN.
  2. Enable multi-factor authentication (MFA) on important accounts.
  3. Use a trusted password manager with a strong master password.
  4. Keep the browser and operating system updated.
  5. Do not save passwords on shared or public computers.
  6. Lock the device when not in use.
  7. Review saved passwords and remove old or unused entries.
  8. Use unique passwords for every account.

Important terms

  • Encryption: changes data into a protected form.
  • MFA: requires another proof of identity besides a password.
  • Password manager: securely stores and manages passwords.

Conclusion: Strong device security, unique passwords, MFA and trusted password storage protect browser credentials.

26.Explain network sniffing and its security risks.

Network sniffing is the process of capturing and examining data packets travelling through a network. It is used by administrators to troubleshoot networks and by investigators to study traffic.

Uses

  • Find network problems.
  • Study traffic and performance.
  • Investigate suspicious communication.

Security risks

  • Attackers may learn network details.

Protection

  • Use HTTPS and secure protocols.
  • Use WPA2 or WPA3 for Wi-Fi.
  • Avoid sensitive activity on unknown public Wi-Fi.
  • Use a VPN when appropriate.
  • Monitor networks and restrict access to packet-capture tools.

Conclusion: Network sniffing is useful for monitoring, but encryption and access control protect data from unauthorised capture.

27.Explain deceptive network connections.

Deceptive network connections are fake or misleading network services or access points designed to attract users or devices. Security teams may also create controlled decoy systems to detect attacks.

Examples

  • Rogue Wi-Fi hotspot: an unauthorised wireless access point that imitates a trusted network.
  • Evil twin: a fake Wi-Fi network using a name similar to a genuine one.
  • Fake login page: a page that imitates a real service to trick users.

Risks

  • Users may connect to an unsafe network.

  • Traffic may be monitored or changed.

Prevention

  • Verify the correct Wi-Fi name with the organisation.
  • Avoid unknown open networks.
  • Use HTTPS and MFA.
  • Disable automatic connection to unknown Wi-Fi.
  • Use authorised honeypots only in controlled environments.

Conclusion: Users should verify network identity, while security teams can use controlled decoys to detect threats.

30.Explain honeypot files and folders.

Honeypot files and folders are decoy items created to attract or detect unauthorised access. They look interesting but contain no real sensitive information.

How they work

  1. A security team creates a decoy file or folder.
  2. It is placed in a monitored location.
  3. Legitimate users are told not to access it, where appropriate.
  4. Access to the decoy creates an alert or log entry.
  5. The security team investigates the activity.

Examples

  • A fake folder named Confidential_Backup.
  • A decoy document containing no real private data.
  • A fake configuration file monitored for access.

Advantages

  • Can give an early warning of suspicious activity.
  • Helps security teams study attacker behaviour.
  • Creates useful alerts with less normal user activity.

Limitations

  • It does not replace antivirus or a firewall.
  • It must be monitored and maintained.
  • It should not contain real passwords or sensitive data.

Conclusion: Honeypot files and folders are useful warning systems for detecting unauthorised access.
